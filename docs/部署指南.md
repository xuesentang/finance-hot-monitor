## 二、第一步：创建 Neon 数据库

### 2.1 注册并创建项目

1. 打开 [https://neon.tech](https://neon.tech)，用 GitHub 账号登录
2. 点击 **"New Project"**
3. 项目名称填 `finance-hot-monitor`
4. 数据库名称填 `finance_hot_monitor`
5. 区域选 `US East (N. Virginia)` —— 和 Render 服务器同区域，延迟最低
6. 点击 **"Create Project"**

### 2.2 获取连接字符串

创建完成后，进入项目 Dashboard：

1. 点击左侧 **"Connection Details"**
2. 在 **" pooled connection "** 标签下，复制连接字符串：
   ```
   postgresql://user:pass@ep-xxxx-pooler.us-east-2.aws.neon.tech/finance_hot_monitor?sslmode=require
   ```
3. 在 **" direct connection "** 标签下，复制连接字符串：
   ```
   postgresql://user:pass@ep-xxxx.us-east-2.aws.neon.tech/finance_hot_monitor?sslmode=require
   ```

> **重要区别**：
> - **Pooled（池化）**：带 `-pooler`，供 Prisma 日常查询用，支持连接池
> - **Direct（直连）**：不带 `-pooler`，仅供数据库迁移（migration）用

把这两个字符串保存到记事本，下一步要用。

## 三、第二步：本地数据库迁移

在部署到 Render 之前，需要先在本地把数据库表结构推送到 Neon。

### 3.1 设置本地环境变量

在项目根目录打开终端，执行：

```powershell
# Windows PowerShell
$env:DATABASE_URL="postgresql://user:pass@ep-xxxx-pooler.us-east-2.aws.neon.tech/finance_hot_monitor?sslmode=require"
$env:DIRECT_URL="postgresql://user:pass@ep-xxxx.us-east-2.aws.neon.tech/finance_hot_monitor?sslmode=require"
```

> 把上面的 `user:pass@ep-xxxx` 替换成你刚才从 Neon 复制的真实值。

### 3.2 推送数据库结构

```bash
cd server
npx prisma db push
```

看到 `Your database is now in sync with your Prisma schema.` 就是成功了。

### 3.3 验证

```bash
npx prisma studio
```

这会打开一个网页界面，如果能看到 Keyword、Hotspot 等表，说明数据库连接正常。

## 四、第三步：部署后端到 Render

### 4.1 推送代码到 GitHub

确保你的代码已经推送到 GitHub 仓库：

```bash
git add .
git commit -m "deploy: add Docker config, adjust cron frequencies, prepare for Render"
git push
```

### 4.2 在 Render 创建服务

1. 打开 [https://dashboard.render.com](https://dashboard.render.com)，用 GitHub 登录
2. 点击 **"New +"** → **"Web Service"**
3. 连接你的 `finance-hot-monitor` 仓库
4. Render 会自动识别根目录的 `render.yaml`，配置如下：
   - **Runtime**: Docker
   - **Plan**: Free
   - **Dockerfile Path**: `./Dockerfile`

### 4.3 设置环境变量

在 Render Dashboard → 你的服务 → **Environment**，添加以下变量：

| Key | Value | 说明 |
|---|---|---|
| `DATABASE_URL` | `postgresql://user:pass@ep-xxxx-pooler...` | Neon 池化连接 |
| `DIRECT_URL` | `postgresql://user:pass@ep-xxxx...` | Neon 直连 |
| `DEEPSEEK_API_KEY` | `sk-xxxxxxxx` | DeepSeek API Key |
| `FRED_API_KEY` | `xxxxxxxx` | FRED API Key（可选） |
| `CLIENT_URL` | `*` | 先填 `*`，等 Vercel 部署后再改 |
| `PORT` | `3001` | 服务端口号 |

> **关于 `CLIENT_URL` 填 `*`**：
> 这是临时设置，让 CORS 允许所有来源。等 Vercel 前端部署完成后，再改成具体的 Vercel 域名。

### 4.4 部署

点击 **"Deploy Web Service"**，等待 3-5 分钟构建。

构建完成后，你会得到一个 URL，例如：
```
https://finance-hot-monitor-api.onrender.com
```

### 4.5 验证后端

在浏览器访问：
```
https://finance-hot-monitor-api.onrender.com/api/health
```

如果返回：
```json
{"status":"ok","timestamp":"2026-05-31T..."}
```

说明后端部署成功！

## 五、第四步：部署前端到 Vercel

### 5.1 创建项目

1. 打开 [https://vercel.com](https://vercel.com)，用 GitHub 登录
2. 点击 **"Add New..."** → **"Project"**
3. 选择同一个 `finance-hot-monitor` 仓库
4. **Framework Preset**: 选 `Vite`
5. **Root Directory**: 填 `client`

### 5.2 设置环境变量

点击 **"Environment Variables"**，添加：

| Key | Value |
|---|---|
| `VITE_API_URL` | `https://finance-hot-monitor-api.onrender.com` |

> 把 URL 替换成你实际的 Render 服务地址。

### 5.3 部署

点击 **"Deploy"**，等待 1-2 分钟。

部署完成后，你会得到一个 URL，例如：
```
https://finance-hot-monitor.vercel.app
```

### 5.4 更新 Render 的 CORS 配置

回到 Render Dashboard → 你的服务 → Environment：

1. 把 `CLIENT_URL` 从 `*` 改成 `https://finance-hot-monitor.vercel.app`
2. Render 会自动重新部署

## 六、第五步：防休眠配置

Render 免费版如果 15 分钟没有请求，会进入休眠状态。下次请求需要 30-50 秒才能唤醒。

### 6.1 使用 cron-job.org 定时唤醒

1. 打开 [https://cron-job.org](https://cron-job.org)，注册账号
2. 点击 **"Create cronjob"**
3. 填写：
   - **Title**: `finance-hot-monitor-health-check`
   - **URL**: `https://finance-hot-monitor-api.onrender.com/api/health`
   - **Schedule**: 每 10 分钟
4. 点击 **"Create"**

这样 Render 就不会休眠了。

## 八、故障排查

### 8.1 服务启动失败

**症状**：Render 显示 Build Failed 或 Deploy Failed

**排查步骤**：
1. 查看 Render Logs 中的错误信息
2. 常见原因：
   - `DATABASE_URL` 填错了 → 检查 Neon 连接字符串
   - `DEEPSEEK_API_KEY` 没填 → 补充环境变量
   - Python 依赖安装失败 → 检查 `scripts/requirements.txt` 格式

### 8.2 数据库连接失败

**症状**：日志中出现 `Can't reach database server`

**排查步骤**：
1. 确认 `DATABASE_URL` 和 `DIRECT_URL` 都填了
2. 确认 Neon 连接字符串包含 `?sslmode=require`
3. 在本地用同样的连接字符串测试：`npx prisma studio`

### 8.3 Python 采集脚本失败

**症状**：日志中出现 `Failed to spawn collector` 或 `collector exited with code 1`

**排查步骤**：
1. 检查 `scripts/requirements.txt` 中的依赖是否都能正常安装
2. 检查 Python 脚本是否有语法错误
3. 在本地测试采集：`python scripts/collector.py --source cailianshe --keywords '["test"]' --watermark '{}'`

### 8.4 CORS 错误

**症状**：前端页面报错 `CORS policy: No 'Access-Control-Allow-Origin'`

**排查步骤**：
1. 检查 Render 的 `CLIENT_URL` 是否设置为 Vercel 的实际域名
2. 确认不是 `*`（某些浏览器不允许 `*` 配合 credentials）
3. 检查前端请求的 API URL 是否正确

### 8.5 定时任务不执行

**症状**：Render Logs 中没有定时任务的输出

**排查步骤**：
1. 确认服务持续运行（没有被休眠）
2. 检查 cron-job.org 的唤醒任务是否正常工作
3. 查看日志中是否有 `node-cron` 相关的错误

## 九、费用与限额

### 9.1 免费额度总结

| 服务 | 免费额度 | 你的用量估算 |
|---|---|---|
| **Render** | 750 小时/月 | 24/7 运行 ≈ 720 小时/月 ✅ |
| **Neon** | 3GB 存储 | 初期 < 100MB ✅ |
| **Vercel** | 100GB 带宽/月 | 10人访问 ≈ 几GB ✅ |
| **DeepSeek API** | 按量付费 | 每月约 ¥15-65 |
| **cron-job.org** | 无限免费任务 | 1个任务 ✅ |

### 9.2 什么时候需要升级

| 场景 | 建议 |
|---|---|
| Render 内存不足（512MB 不够） | 升级到 Starter ($7/月) |
| Neon 存储超过 3GB | 升级到 Launch ($19/月) |
| 用户数超过 50 人 | 考虑分离部署或升级 Render |
| DeepSeek API 费用过高 | 进一步降低采集频率或减少关键词 |

## 十、安全注意事项

1. **不要把 `.env` 文件提交到 GitHub** —— 已配置 `.gitignore`
2. **不要在代码中硬编码 API Key** —— 始终使用环境变量
3. **定期轮换 API Key** —— 尤其是 DeepSeek 的 Key
4. **Neon 连接字符串包含密码** —— 不要分享给他人
